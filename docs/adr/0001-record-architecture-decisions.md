# 1. Record architecture decisions

Date: 2026-06-16

## Status

Accepted

## Context

This is a template meant to be reused as the starting point for real systems. The
value is not only the code but the reasoning behind it. Decisions that are
obvious to the author today are opaque to a teammate, or to the author in a year.

## Decision

We keep short Architecture Decision Records (ADRs) in `docs/adr`, one per
significant decision, in the format: Status, Context, Decision, Consequences.

## Consequences

The "why" travels with the code. When a decision is revisited, its ADR is
superseded rather than silently overwritten, so the history of the design stays
legible.
